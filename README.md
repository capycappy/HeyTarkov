# Hey Tarkov v1.2.1

マイクボタンを押している間に**タスク名・マップ名・脱出地点名**を言うと、
Escape from Tarkov の Wiki の該当ページをブラウザで開くデスクトップアプリ。
**日本語（カタカナ読み）と英語の両対応**、**日本語 Wiki と英語 Wiki の両対応**。

## アプリは Wiki に一切アクセスしません

一覧（1056件）は**ビルド時にアプリへ埋め込まれた固定データ**です。
アプリが実行中に Wiki へリクエストを送ることはありません。やっているのは
**ブックマークと同じく、ブラウザで該当ページを開くこと**だけです。

一覧の更新は開発者が `tools/CatalogBuilder` を手動で実行し、新しいバージョンとして
リリースする形をとります。利用者側での自動更新はありません。

アプリが通信するのは1点のみ、**GitHub Releases に新しいバージョンがあるかの確認**です。

## ダウンロード

[Releases](https://github.com/capycappy/HeyTarkov/releases) から ZIP を取得して展開するだけ。
インストーラはない。

| | サイズ | 必要なもの |
|---|---|---|
| `HeyTarkov-v1.2.1-win-x64.zip` | 42MB | **なし**（これを選べばよい） |
| `HeyTarkov-v1.2.1-win-x64-framework-dependent.zip` | 0.6MB | .NET 10 Desktop Runtime |

## つかいかた

1. `HeyTarkov.exe` を起動（Alt+Tab で切り替えて使う想定）
2. 上部のカードで 言語 / Wiki / ブラウザ / 入力デバイス を選ぶ（一度きり）
3. **丸いマイクボタンを押しっぱなし**にして、タスク名を言う
4. 離すと認識 → 候補が出る。確信度が高ければそのままブラウザで開く

聞き取り中は**認識途中の文字列がリアルタイムで表示される**。確信度が足りず棄却された場合も、
何と聞こえたかを表示したうえで近い候補を並べる（黙って失敗しない）。

### 途中まで言えば候補が出る

**フルネームを言う必要はありません。**「ブロードキャスト」だけで `Broadcast - Part 1〜5`
が候補に並びます。断片は1件に確定できないので候補を出すだけで、自動では開きません
（フルネームを言ったときだけ自動で開きます）。

助詞・冠詞だけの断片と4文字未満の断片は、誤爆するだけなので対象外です。
候補は名前順に並び、数字は数値として比較します（`Part 10` は `Part 2` の後）。

### 言えるもの

| 種別 | 件数 | 例 |
|---|---|---|
| タスク | 898 | 「ウェット ジョブ パート フォー」 |
| マップ | 15 | 「グラウンドゼロ」 |
| 脱出地点 | 143 | 「グラウンドゼロ エマーコムチェックポイント」 |

脱出地点はマップ名を省略できます。ただし `Emercom Checkpoint` のように複数マップに
同名がある場合、マップ名を付けると一意に決まります。
候補リストには種別と陣営が出ます（`[出口] Emercom Checkpoint (PMC)`）。

| モード | 「Wet Job - Part 4」の言い方 |
|---|---|
| 日本語 | ウェット ジョブ パート フォー / … パート ヨン |
| 日本語（スペル読み） | ダブリュー イー ティー　ジェー オー ビー　ピー エー アール ティー　フォー |
| 英語 | wet job part four / wet job part 4 |

**発音がわからないタスクは、アルファベットを読み上げれば通る。**
`Fall Ailment` → `エフ エー エル エル　エー アイ エル エム イー エヌ ティー`
実測では単語読みより確信度が安定している（例: Shortage は単語 0.31 → スペル 0.87）。
候補リストには各タスクのカタカナ読みも表示されるので、言い方はそこで確認できる。

ボタンにフォーカスがある状態なら **Space キー長押し** でも同じ。
音声を使わずキーボードで探すこともできる（下の検索ボックス、英語表記で入力）。

### Wiki の選択

| | |
|---|---|
| 日本語 Wiki | [wikiwiki.jp/eft](https://wikiwiki.jp/eft/) — 586件 |
| 英語 Wiki | [escapefromtarkov.fandom.com](https://escapefromtarkov.fandom.com/wiki/Quests) — 870件 |

**選択中の Wiki にページがある項目だけが認識・検索の対象**になる。
片方にしか無いタスクを候補に混ぜると、実際に開けるタスクが下に押し下げられて邪魔になるため。
Wiki を切り替えると文法と検索インデックスの両方が組み直される。
ストーリータスクも両方から取得している。

**脱出地点だけは両 Wiki で精度が違う。** wikiwiki は脱出地点ごとに見出しがあるので
`GROUND ZERO#j60a102a` のように出口そのものへ飛べる。英語 Wiki は全出口が
`#Extractions` の1つの表にまとまっているため、**表までしか飛べない**（向こうの
ページ構造上の制約で、実装の手抜きではない）。

### 画面

**マイクボタンと入力レベル計は同じ丸**。押している間だけ下から満ちる。
声を出さないと何も動かないので、待機中に描き直すものは画面上に一つも無い。

**話す**（丸）と**打つ**（検索ボックス）は同じ行に並ぶ。同じ目的の二つの入口なので、
構造として同じ高さに置いてある。設定は上のカードに畳んであり、残りは候補の場所。

候補は1行に**種別・名前・トレーダー・一致度・カタカナ読み**の列を持ち、
タスク / マップ / 出口が色で分かれる。

明暗どちらのテーマでも同じ。100% から 200% までの拡大率で正しく追従する
（別解像度のモニターへ移してもレイアウトは崩れない）。

**ウィンドウの位置と大きさは前回終了時のものを覚える。** どのモニターのどこに置いたかも含む。
そのモニターが無くなっていたら中央に戻す（画面外に開いて掴めなくなることはない）。
最大化したまま閉じれば最大化で開き、元に戻すと最大化する前の形に戻る。

### 入力デバイスとブラウザ

オーディオインターフェースでは入力が複数系統に分かれて見えるため、
Windows の既定デバイスが目的のマイクとは限らない。ドロップダウンで選べる。

ブラウザは Windows に登録されているものから選択できる（既定のブラウザ / Chrome / Edge /
Firefox / Brave など）。選択はすべて記憶され、名前で照合するのでインデックスがずれても追従する。

**「レベル確認」ボタン**は認識器を介さずに入力レベルだけを表示する。
「マイクが拾っていない」のか「認識が一致しなかった」のかを切り分けるためのもの。
`再検出` は起動後に機器を繋ぎ替えたときに使う。

**表示はマイクボタンそのものが兼ねる。** 丸が下から満ちるのが今の音量、
残る線がこれまでの最大値、その線の色が判定。線が下から動かなければマイクが小さすぎる。

レベルの数値は **dBFS** で最下段に出す。0 dBFS が歪む限界で、健全な音声はピーク
-20 dBFS 前後に収まる。線形のパーセント表示だと「10%」のように見えて壊れていると
錯覚するため。

| ピーク | 判定 |
|---|---|
| -50 dBFS 未満 | 無音（何も入っていない） |
| -50 〜 -35 | 小さすぎ（ゲインを上げる） |
| -35 〜 -3 | 十分 |
| -3 以上 | 大きすぎ（歪む恐れ） |

### 表示テーマ

下部の「表示」で **システムに従う / ライト / ダーク** を選べる（初期値はシステム追従）。
WinForms はプロセス起動時に描画方式を決めるため、切り替えるとアプリが自動で再起動する。

### バージョン確認

起動時に GitHub Releases を確認し、今より新しいものがあれば画面上部に
「新しいバージョン v1.0.1 があります（クリックで開く）」と表示する。
オフライン・レート制限・リリース未公開のときは何も出さない。

タスク一覧が更新されるのはこのアプリ本体の更新時だけなので、**この通知が
「新しいタスクが入った版が出た」の合図**になる。

## 必要なもの

- Windows 11（自己完結版ならランタイムの導入は不要）
- 日本語モード: 日本語の音声認識（Windows 標準で入っていることが多い）
- 英語モード: 英語(米国)の音声認識
  - 設定 → 時刻と言語 → 言語と地域 → English (United States) → 言語のオプション → 音声認識
  - 管理者 PowerShell なら `tools\install-en-speech.ps1`
  - ダウンロードに非常に時間がかかることがある（進捗が動かなくても待つ）

インストール済みの認識エンジンはアプリ下部のステータス行に表示される。

## しくみ

| | |
|---|---|
| 一覧 | ビルド時に埋め込まれた `tasks.json`（1056件）。実行時に取得はしない |
| 前方一致 | 名前の先頭からの語の並びをすべて文法に入れ、断片は候補リストに解決する |
| 音声認識 | Windows 標準 (SAPI)。語彙をタスク名のフレーズに限定したクローズドグラマー |
| 日本語の読み | 名前に出てくる**1184語＋数字33種**の読みを `japanese-lexicon.json` に登録し、単語単位で合成 |
| 英語の読み方の吸収 | `Gunsmith - AKS-74N` → `gunsmith aks 74 n` / `... seventy four n` / `... a k s seven four n` |
| 日本語の読み方の吸収 | 数字は英語読み・日本語読みの両方（`ナナヨン` / `セブンティフォー`） |
| スペル読み | タスク名をアルファベット読みに展開（30文字以内のもの、894件）|
| 間の許容 | **文法フレーズは必ず語で区切る。**スペースなしの1語にすると、その途中で息継ぎした時点で一致しなくなる |
| 取りこぼし | 完全一致しなければ Levenshtein で近い候補を最大6件出す |

読みが未登録の単語を含むタスクも**除外しない**。スペル読みでは認識できるようにしてあり、
不足単語は `%LOCALAPPDATA%\HeyTarkov\missing-readings.txt` に書き出される。

## 検証結果

`--selftest` による、合成音声を認識器に食わせるエンドツーエンド確認:

```
covered       : 1056/1056
English    9/9 passed   (2627 phrases, grammar load  141ms)
Japanese  17/17 passed  (2565 phrases, grammar load 1630ms)
                        + スペル読み 1123 phrases, 121ms
```

これに加えて、音声を使わない回帰テストが3種:

- **読み未登録の単語**を含む項目がスペル読みで引けること
- **マップと脱出地点**が解決し、出口のリンクにアンカーが付いていること
  （`Emercom Checkpoint (PMC)` が `GROUND%20ZERO#j60a102a` を指すことを実URL照合）
- **断片**が正しいグループに解決し、名前順に並ぶこと

日本語17件の内訳は、単語読み8・スペル読み4・**1文字ごとに600msの間を空けたスペル読み4**・
**マイクと同じストリーム入力経路1**。加えて、辞書に無い単語を含むタスクが
スペル読みで引けることを確認する回帰テストが1件。

合成音声は肉声よりはるかに認識しやすいため、これは配線の正しさを示すもので、
実際の精度を保証するものではない。

## 動作コスト

実測（起動 → 認識エンジン読み込み済み → アイドル）:

- メモリ 約 138MB
- **アイドル時 CPU 0%**
- EXE 1.5MB（単一ファイル、データ同梱）

マイクはボタンを押している間だけ掴み、離すと解放する。待機中はオーディオデバイスを一切保持しない。
文法のコンパイルはバックグラウンドスレッドで行うため、UIは固まらない。

### 語の区切りが効く

当初スペル読みを「スペースなしの1フレーズ」として登録していたが、これには2つの問題があった。

1. 1語の途中で息継ぎすると一致しない（`no recognition` になる）
2. 長大な語が認識器の辞書に載るため、コンパイルに **7.5秒** かかった

1文字ずつ独立した語に分けたところ、辞書はカタカナ26文字分に縮み、
**コンパイル 7538ms → 73ms**、かつ1文字ごとに600msの間を空けても認識できるようになった。

### System.Speech にストリームを渡すときの2つの罠

入力デバイスを選べるようにするため、自前で取り込んだ音声を
`SetInputToAudioStream` に渡している。ここで**どちらも例外を出さずに
「一切認識しない」形で失敗する**条件が2つあった。`--streamdiag` で切り分けた結果:

```
H) CanSeek=false                        : NO RECOGNITION
I) CanSeek=true, Length=exact           : OK
J) CanSeek=true, Length=long.Max        : OK

M) 1回のReadで最大1024バイトしか返さない  : NO RECOGNITION
N) 同上 + 40ms遅延                       : NO RECOGNITION
O) 要求サイズを必ず埋める + 40ms遅延       : OK
P) 実LiveAudioStreamに50ms刻みで実時間供給 : OK
```

1. **`CanSeek` は `true` でなければならない。** このため録った音声を全部保持している。
2. **`Read` は要求されたバイト数を必ず埋めなければならない。** 短い読み取りは
   音声終端と解釈される。

`Stream.Length` は読み取り上限として一度だけ参照されるので `long.MaxValue` を返し、
実際の終端は capture 終了後に `Read` が要求より少なく返すことで伝える。
この2点は `LiveAudioStream` に集約してあり、`--streamdiag` のケース P が実クラスを検証する。

※ コンパイル済み文法のディスクキャッシュも試したが、.NET 版 System.Speech では
`new Grammar(path)` が `PlatformNotSupportedException` を投げるため使えない。

## アンチチートについて

このアプリはゲームに一切触れない。設計上、以下を**行わない**:

- ゲームプロセスのメモリ読み書き / DLL インジェクション
- DirectX フック、ゲーム内オーバーレイ
- ゲームウィンドウへの合成入力送信（SendInput 等）
- カーネルドライバ
- グローバルホットキー（自ウィンドウのボタンで完結するため不要）
- EXE のパッキング・難読化（`EnableCompressionInSingleFile=false`）

やっているのは「マイクから録音」「文字列一致」「ブラウザを起動」の3つだけで、
ブラウザのショートカットをダブルクリックするのと同じ挙動しかしない。

音声取り込みには NAudio（WinMM のみ）を使っている。標準の録音APIを叩くだけで、
フックもドライバも含まない。

## ビルド

```
dotnet publish src\HeyTarkov -c Release -o dist
```

`dist\HeyTarkov.exe` が単一ファイルの成果物。付随ファイルは不要。

`NuGet.Config` はこのリポジトリ内だけで nuget.org を有効にしている。

### タスク一覧の更新（開発者向け）

```
dotnet run --project tools\CatalogBuilder
```

両 Wiki から一覧を取り直して `src\HeyTarkov\tasks.json` を書き換える。
**アプリ本体とは別プロジェクト**で、配布物には含まれない。
実行後にアプリをビルドし直すと新しい一覧が埋め込まれる。

その後 `--selftest` を走らせると、新しいタスク名に読みが足りているかが確認できる。
足りない単語は `japanese-lexicon.json` に追記する。

### アイコン

`tools\IconMaker` がアイコンをコードから生成する（[docs/ICON.md](docs/ICON.md)）。

```
dotnet run --project tools\IconMaker
```

### 診断コマンド

```
HeyTarkov.exe --selftest     # 合成音声で英語・日本語の認識を通しで検証
HeyTarkov.exe --mictest 6    # 実マイクで6秒録音し、全段階を報告
HeyTarkov.exe --devices      # 入力デバイスを列挙し、実際に開いて録れるか確認
HeyTarkov.exe --streamdiag   # ストリーム入力経路の切り分け（CanSeek/Length/再利用）
HeyTarkov.exe --checkupdate  # 起動時バージョン確認が何をするかを実行して報告
```

結果は `%LOCALAPPDATA%\HeyTarkov\` に `*-report.txt` として出力される。
